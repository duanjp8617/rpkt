# Bounded two-machine DPDK loopback

The final 17 runs returned **334,248,607 marked UDP packets with zero IPv4 or
UDP checksum errors**. The adjacent JSONL file retains both endpoint counters
for every run. These are controlled end-to-end loopback measurements, not a
claim of maximum forwarding capacity or a universal offload speedup.

## Verified wiring and environment

The links were identified with unique raw diagnostic frames and capture on the
peer, not inferred from port numbering. Both links report 100 Gbit/s/full duplex.

- duanjp: Xeon Platinum 8580, CPU 60 (SMT sibling 180), NICs on NUMA node 2,
  ConnectX-7, mlx5_core 2607.0.100, firmware 28.44.1036,

- Two ports allowlisted per process, one worker, one RX/TX queue per port,

Run the commands in [the example instructions](../../rpkt-dpdk/README.md#bounded-two-port-loopback),
using forwarder duration 10 seconds and generator duration 3 seconds. Wait for
the forwarder's READY before starting tg. All final rows use `rx_vec_en=0` on
both devices, on both hosts, so the RX implementation is held constant across
burst sizes. The generator adds a 200-ms RX drain. Sizes include Ethernet but
exclude FCS, preamble and interpacket gap. Each frame carries sequence/timestamp;
every 1024th sequence is sampled for RTT on tg's own clock.

metric across the three runs, not a combined percentile or a selected best run.
The raw records retain variation and exact counts.

| 1500 | NIC | 3.158 | 3.157 | 0.038 | 325.922 / 355.738 / 375.068 |

Offload mode skips the generator's software payload-checksum scan, requests the
installed headers' **IPv4 and UDP** port capabilities, sets L2/L3/L4 lengths and
TX mbuf flags, clears the IP checksum and supplies the UDP pseudo-header seed.
Both returned checksums are still validated in software. Forwarding changes TTL
using RFC 1624 only after validating the original IPv4 checksum. NIC mode was
actually available in every offload row (see `tx_offload: true`).

All final runs had zero allocation-empty, TX-error, RX-no-mbuf, partial-TX and
unsent counters. Queue congestion/drop counts are not zero: unreturned marked
packets reconcile with the two RX-missed counters. Some runs saw a handful of
unrelated/invalid frames, separately counted and never forwarded. No lossless
or line-rate claim is made. Earlier exploratory vector-RX runs exercised
partial TX (including 4151 partial bursts), but are excluded from this final
comparison because their capability masks were corrected during review.

## Profiling and decisions

One of the three 64-byte/software/burst-32 runs (`final-13`) wrapped the entire
forwarder with:

```sh
perf stat -x, -e cycles,instructions,branches,branch-misses,cache-references,cache-misses -- COMMAND
```

It recorded 29,216,420,080 cycles, 83,083,028,460 instructions,
12,330,385,206 branches, 8,825,373 branch misses (0.07%), 62,730,843 cache
references and 5,866,305 cache misses (9.35%). Counters ran 100% of the time.
Dividing by 27,998,145 forwarded packets gives **1043.51 whole-process
cycles/packet**, including initialization and roughly seven seconds of idle
polling. This must not be interpreted as active-path service cost. No source
checks were removed based on these counters, and they do not establish a
memory-stall bottleneck that would justify speculative application prefetching.

The native run exposed and fixes physical-package versus NUMA-node confusion
in `Lcore::socket_id`: duanjp CPU 60 is package 1 but NUMA node 2. A native test
compares all reported CPUs with DPDK, including builds with NUMA disabled.
mlx5 vector RX also cannot serve burst 1; the example documents/guards its
scalar-RX requirement. Link readiness and a version-independent C link wrapper
avoid startup artifacts and DPDK 21.11/24.11 bitfield-layout differences.

The batching, per-worker counters, local pools and bounded partial-TX handling
are retained. Offload remains optional and capability-checked with a software
fallback. The fallback branch is implemented but was not exercised by these
capable NICs. Jumbo frames, TCP, multi-worker scaling and other PMDs were not
part of this live matrix; no performance claim is made for them.
