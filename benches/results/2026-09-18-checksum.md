# Checksum experiment, 2026-09-18

The opt-in `simd` feature retains the portable loop for short inputs and uses
runtime-guarded AVX2 from 512 bytes. A four-accumulator scalar prototype was
rejected after initial timings regressed; it is not part of the implementation.
The existing scalar loop now folds every 65536 bytes to prevent overflow.

On `tg`: Intel Xeon Gold 6230, Linux 5.15.0-185-generic, Rust 1.98.0 / LLVM
22.1.8, committed Cargo.lock, bench profile fat LTO/one codegen unit, no extra
RUSTFLAGS, taskset CPU 2, contiguous aligned input. Command:

```sh
taskset -c 2 cargo bench --locked -p benches --bench matrix --features simd -- \
  'checksum_bytes/slice_align0/(64|128|512|1500|9000)$' \
  --save-baseline avx2-1 --noplot --nresamples 1000
```

Repeat three times with distinct labels; omit `--features simd` for scalar.
Each case uses 20 samples, 100 ms warmup, 200 ms measurement. Values below are
the median of the three central estimates, in ns per call (not CPU cycles).

| Bytes | Bounded scalar | AVX2 prototype | Scalar / AVX2 |
| --- | ---: | ---: | ---: |
| 64 | 6.81 | 6.91 | 0.99 |
| 128 | 10.57 | 10.75 | 0.98 |
| 512 | 32.91 | 21.41 | 1.54 |
| 1500 | 96.05 | 50.41 | 1.91 |
| 9000 | 542.53 | 243.23 | 2.23 |

The prototype dispatched at 128; the shipped cutoff is 512 because no benefit
was observed at 128. All three 512/1500/9000 comparisons favor AVX2. For 9000
bytes the scalar 95% intervals were [671.35,730.53], [533.22,543.40],
[539.30,546.13] ns; AVX2 intervals were [237.51,241.67], [243.12,257.57],
[241.39,245.82] ns. Frequency/load variation between runs is visible. These are
warm-buffer checksum measurements and do not predict forwarding throughput.
Governor/turbo settings were not changed or controlled; repeat on deployment CPUs.

Local i5-13500H testing also showed a long-input benefit. Optimized assembly
contains bounded unaligned loads, `vpsadbw` and independent `vpaddq` accumulators.
In the local release rlib, `nm -S` reports 378 bytes for the AVX2 kernel, 377 for
the scalar block, and 190 for dispatch (before downstream LTO). No native NEON
backend is retained because no AArch64 validation host is available. No batch
SIMD or wide template stores are inferred to be beneficial from this experiment.

Correctness checks compare both kernels against a separate per-word reference:
all lengths 0–259, dispatch/folding boundaries, offsets 0–31, random/all-ones
inputs, odd segments and buffers beyond the old accumulator overflow limit.
Default and SIMD tests pass natively; the no_std fallback builds for
thumbv7em-none-eabi. Miri deliberately follows the scalar path.
